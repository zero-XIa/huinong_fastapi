# 慧农项目全局规范（完整版）
## 一、技术栈与基础环境
- **后端**：Python 3.12 + FastAPI + SQLAlchemy + MySQL
- **前端**：Flutter 3.24+，Dart 3，空安全
- **网络层**：Dio 5.0+（单例、拦截器、统一错误处理）
- **状态管理**：Provider（轻量，`app_provider.dart` 管理适老化模式等）
- **样式**：两套配置（默认 Material Design + 适老化国家规范）
- **开发顺序**：先通联 → 再功能 → 再优化 → 最后美化
## 二、后端接口基础信息
- **Base URL**：`http://127.0.0.1:8000/api/v1`
- **API 版本**：v1，路径前缀 `/api/v1`
- **认证方式**：JWT Token，有效期 2 小时
  - 请求头：`Authorization: Bearer <token>`
  - 不需要认证的接口：`POST /users/register`、`POST /users/login`、`GET /`
- **请求格式**：
  - 普通数据：`application/json`
  - 文件上传：`multipart/form-data`，文件字段名固定为 `file`
- **响应格式**：`application/json`
## 三、统一响应格式（规范版）
### 成功响应
- **HTTP 状态码**：`200 OK`
- **响应体**：

```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```

### 客户端错误（4xx）

- **HTTP 状态码**：对应 400、401、403、404、409 等
- **响应体**：

```json
{
  "code": 40001,
  "message": "具体错误原因",
  "data": null
}
```

### 服务器错误（5xx）

- **HTTP 状态码**：`500 Internal Server Error`
- **响应体**：
```json
{
  "code": 50000,
  "message": "服务器内部错误，请稍后重试",
  "data": null
}
```

### HTTP 状态码与业务 code 映射表

| 场景               | HTTP 状态码 | 业务 code 范围  | 示例 code |
| ---------------- | -------- | ----------- | ------- |
| 成功               | 200      | 200         | 200     |
| 参数校验失败           | 400      | 40001~40099 | 40001   |
| 未授权（Token 无效/过期） | 401      | 40101~40199 | 40101   |
| 无权限              | 403      | 40301~40399 | 40301   |
| 资源不存在            | 404      | 40401~40499 | 40401   |
| 资源冲突（已存在）        | 409      | 40901~40999 | 40901   |
| 服务器内部错误          | 500      | 50000~50099 | 50000   |
**前端处理建议**：优先判断 HTTP 状态码（如 401 直接跳转登录），再根据业务 `code` 展示具体错误信息。

## 五、通用校验规则

- **用户名**：长度 3-50，只允许字母、数字、下划线
- **密码**：长度 8-20，必须包含字母和数字（后端使用 bcrypt 哈希存储）
- **手机号**：可选，如果提供则必须是 11 位数字，以 1 开头
- **分页参数**：
	- `skip`：整数，≥0，默认 0
	- `limit`：整数，1-100，默认 10
- **图片上传**：
	- 格式：jpg / jpeg / png
	- 大小：≤ 10MB
	- 字段名：`file`
## 六、时间格式

- 统一使用 **ISO 8601 UTC**，示例：`2026-04-16T10:00:00Z`

## 九、WebSocket 接口（智能问答）

- **URL**：`ws://127.0.0.1:8000/ws/chat?token=<jwt_token>`
- **发送报文**：
```json
{ "content": "用户问题", "session_id": "可选" }
```

- **接收报文（流式）**：
```json
{ "role": "ai", "content": "逐字文本", "is_end": false }
```

- 结束时 `is_end: true`
- 连接成功会返回：
```json
{ "type": "connected", "session_id": "xxx" }
```

- `type` 字段取值说明：
  - `connected`：连接成功
  - `error`：错误响应
  - `message`：流式消息（也可直接使用 role/content/is_end 结构）

## 十一、样式与适老化规范

### 默认样式（简洁大气）

- Google Material Design，主色 `#2E7D32`（绿色），背景白色/浅灰
- 极简动效，布局间距统一

### 适老化样式（国家规范）

- **字体**：标题 ≥20px，正文 ≥18px，按钮文字 ≥19px，无细体/斜体
- **配色**：高对比度，文字 `#333333`，背景 `#F5F5DC`
- **交互**：按钮高度 ≥50px，圆角 ≥12px，间距 ≥20px，无滑动验证/复杂动画
- **切换**：通过“我的”页面开关控制，实时生效，后端存储 `elder_mode` 字段
- **实现建议**：在 `AppProvider` 中存储 `elder_mode`，通过 `Consumer` 重建 `MaterialApp` 的 `theme` 和 `textTheme`。

## 十二、开发协作规则（AI 可作为主导）

- **AI 角色**：你可以作为主导开发者，依据本规范自主完成代码实现、接口对接、错误修复等任务。
- **职责范围**：负责生成完整代码、设计数据库模型、编写接口逻辑、前端页面与状态管理、调试错误。
- **限制**：不得随意变更已有架构（如分层结构、全局变量命名）；不得引入未在规范中说明的新技术栈；不得破坏已有功能的稳定性。
- **输出要求**：提供可直接运行的代码片段，附带必要的解释（如关键逻辑、潜在风险）。优先遵循“小步骤、可落地”原则。
- **错误处理**：遇到不确定的问题，先分析原因（前端/后端/路径/权限/格式），给出解决方案；如果方案可行性低，请直接说明并建议替代方案。
- **对接要求**：
    - 所有接口调用基于已封装的 Dio 单例
    - 响应数据必须解析为 null-safe 的 Model 类，禁止直接用 Map
    - 请求时显示加载中，失败时弹出中文提示，成功后跳转/更新页面
- **重大变更确认**：若需新增数据库表、引入新的第三方库、修改项目根目录结构，应先说明理由并等待用户确认。

## 十三、其他约定

- **跨域（CORS）**：后端已配置，开发环境允许所有来源
- **数据库**：MySQL，表名前缀 `tb_`（如 `tb_user`, `tb_news`, `tb_identification`, `tb_message`）
- **密码安全**：后端必须使用 bcrypt 哈希，前端不存储明文密码
- **异步处理**：所有网络请求、本地存储、样式切换必须异步，避免阻塞 UI
- **代码复用**：新增功能时复用已有封装（Dio 实例、通用组件），不重复造轮子
- **角色权限**：用户表增加 `role` 字段（`user` / `admin`），管理员接口需要校验角色
- **调试规范**：开发阶段后端可使用 `print` 或 `logging` 输出关键请求信息；前端可使用 `debugPrint`。方便定位问题。
